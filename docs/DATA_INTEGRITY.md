# 데이터 무결성 검증 (Step 5)

작업지시서 2.2 의 두 원칙 — **임의의 가짜 데이터 생성 금지**, **출처 표기 의무화** — 이
코드에서 실제로 어떻게 강제되고 무엇으로 검증되는지 정리한 문서다.

문서로만 적어 둔 규칙은 지켜지지 않는다. 아래 항목은 모두 **테스트로 고정**되어 있어,
나중에 규칙을 어기는 변경이 들어오면 빌드가 실패한다.

---

## 1. 가짜 데이터 금지

### 1.1 값이 없으면 값을 만들지 않는다

| 지점 | 없을 때의 동작 | 검증 |
| :--- | :--- | :--- |
| `MoneyFormatter.parseManwon` | `null` | `MoneyFormatterTest` |
| `AreaFormatter.parseAreaM2` | `null` (0 이하도 `null`) | `AreaFormatterTest` |
| `TradeDateWindow.parseDealDate` | `null` (2/30 을 2/28 로 당기지 않음) | `TradeDateWindowTest` |
| 응답의 한 행 | 행을 버리고 **사유·건수를 남김** | `ParserIntegrityTest` |
| 조회 결과 0건 | `거래 데이터 없음` 표시 | `MolitParserTest` |
| 조회 실패 | 오류 문구 그대로 노출 (빈 목록으로 뭉개지 않음) | `FeedViewModelTest` |
| 인증키 미설정 | 조회를 시도조차 하지 않음 | `TradeRepositoryImplTest` |

`ParserIntegrityTest` 는 필수 필드(거래금액·전용면적·계약일·보증금·월세·단지명·법정동)
각각에 대해 **태그 없음 / 빈 태그 / 공백 / 숫자 아님** 네 가지 형태를 모두 넣어,
어떤 경우에도 `0원`·`0㎡` 같은 값이 새어 나오지 않는지 확인한다.

### 1.2 타입으로 막는다

- `TradeValue<T>` 는 `Reported` / `Missing` 두 갈래뿐이다. 값이 없는 경우를 호출부가
  반드시 다루게 된다. **기본값으로 채우는 오버로드는 의도적으로 없으며**, 그런 이름
  (`orElse`, `getOrDefault`, `orZero` 등)이 추가되면 `SourceIntegrityTest` 가 실패한다.
- 필수 값(거래금액·전용면적·보증금)은 non-null 이라 JVM 에서 primitive 로 컴파일된다.
  선택 값(층·준공연도)은 박싱 타입이다. 구조만 봐도 필수/선택이 구분되며,
  이 구조를 리플렉션으로 확인한다.

### 1.3 운영 코드에 지어낸 값이 없다

`SourceIntegrityTest` 가 `src/main` 의 모든 Kotlin 파일을 훑는다 (주석·문자열 제외).

- 난수 생성 (`Random`, `Math.random`) → 없음
- `mock` / `dummy` / `fake` / `sample` / `placeholder` / `lorem` 식별자 → 없음
- 테스트 픽스처 참조 (`molit/`, `test/resources`, `getResourceAsStream`) → 없음
- `@Preview` → 없음. Compose 미리보기는 샘플 데이터가 스며드는 대표적인 통로다.
  꼭 필요하면 `debug` 소스셋으로 분리하고 이 검사에서 제외해야 한다.

> 이 검사가 실제로 동작하는지 확인하려면 `src/main` 아무 파일에 난수나 `dummy` 를
> 넣고 `SourceIntegrityTest` 를 돌려 보면 된다. 실패해야 정상이다.

### 1.4 성사되지 않은 가격은 기준으로 쓰지 않는다

계약 해제 건은 신고된 사실이므로 목록·이력에는 남기되(취소선 + `계약 해제` 배지),
**가격의 근거로는 쓰지 않는다.**

| 쓰임 | 해제 건 처리 | 검증 |
| :--- | :--- | :--- |
| 피드의 직전 대비 등락률 | 비교 기준에서 제외 | `FeedBuilderTest` |
| 상세 차트의 점 | 찍지 않음 | `ChartBuilderTest` |
| 기간 내 최고가 가이드라인 | 후보에서 제외 | `ChartBuilderTest` |
| 세로축 범위 | 제외 (30억 해제 건이 축을 왜곡하지 않음) | `ChartBuilderTest` |
| 거래 이력 표 | **남김** (취소선 표시) | `DetailUiStateTest` |

### 1.5 모르는 구간을 아는 척하지 않는다

- **등락률**: 불러온 데이터 안에 같은 단지·같은 평형의 앞선 거래가 없으면 표시하지 않는다.
  기준값을 추정해 만들지 않는다.
- **차트 선**: 신고가 오래 없던 구간(기간의 1/6 초과)은 선을 끊고 점만 남긴다.
  점은 실제 신고된 거래, 선은 가까운 두 관측 사이에서만 그린다.
- **로딩 화면**: 스켈레톤은 회색 막대만 쓴다. 실제 값처럼 보이는 숫자를 넣지 않는다.

### 1.6 캐시가 원자료보다 오래되지 않게 한다

지연 신고와 계약 해제는 나중에 반영된다. 행을 합치지 않고 **(지역 × 계약월) 단위로
통째로 갈아끼워서**, 캐시가 국토교통부 자료의 현재 상태를 그대로 따라가게 한다.
(`TradeRepositoryImplTest` — 같은 달을 다시 받으면 이전 행을 지우고 새로 넣는지 확인)

## 2. 출처 표기

`AttributionCoverageTest` 가 **화면이 가질 수 있는 모든 상태**를 만들어, 어느 하나에서도
출처가 사라지지 않는지 확인한다.

- 피드: {로딩, 목록, 결과 없음, 오류} × {동기화 전, 동기화 후} = 8가지
- 상세: {로딩, 결과 없음, 동기화 후} = 3가지

표기 위치:

| 위치 | 문구 |
| :--- | :--- |
| 목록 카드마다 | `국토교통부 실거래가 공개시스템 · 기준 YYYY-MM-DD hh:mm` |
| 피드 화면 하단 고정 바 | `데이터 출처: 국토교통부 실거래가 공개시스템 (기준일시: …)` |
| 상세 화면 하단 고정 바 | 동일 |

- 아직 받아온 적이 없으면 `(아직 동기화되지 않음)` 으로 표기하고,
  **지금 시각을 기준일시처럼 적지 않는다.**
- 출처 문구는 `DataSourceAttribution` 한 곳에만 둔다. 화면마다 따로 적으면 하나가
  빠져도 알아채기 어렵다. 다른 파일에 같은 문구가 생기면 `SourceIntegrityTest` 가 실패한다.

## 3. 테스트 픽스처에 대하여

`app/src/test/resources/molit/` 의 XML 은 **응답 구조**를 재현한 파서 테스트 입력이다.

- 실제 실거래 데이터가 아니다. 단지명은 `파싱테스트아파트` 처럼 실존하지 않는 이름을 쓴다.
- 파일마다, 그리고 그 폴더의 `README.md` 에 그 사실을 명시했다.
- **운영 코드는 이 폴더를 참조하지 않는다** (`SourceIntegrityTest` 로 고정).
- 목적은 "필드가 비었을 때 조용히 기본값으로 채우지 않는가" 를 확인하는 것이다.

## 4. 아직 검증되지 않은 것

정직하게 남겨 둔다. 최초 연동 시 반드시 확인할 것.

### 4.1 응답 필드명 — **실응답 대조 필요**

`aptNm`, `excluUseAr`, `dealAmount`, `deposit`, `monthlyRent`, `cdealType`, `cdealDay`,
`sggCd`, `umdNm`, `dealYear/dealMonth/dealDay` 등은 공공데이터포털에 공개된 응답 명세를
따랐으나, 개발 환경에서 data.go.kr 에 접속할 수 없어 **실제 응답으로 검증하지 못했다.**

다만 어긋나도 조용히 실패하지 않는다. 필드명이 맞지 않으면 값이 비는 게 아니라
"읽지 못한 행" 으로 집계되어 아래에 드러난다.

- `SyncReport.parseFailures`
- `sync_state.failureCount` (DAO: `SyncStateDao.withParseFailures()`)
- 화면 상단 알림 배너 — "국토교통부 응답 중 N건을 읽지 못해 목록에서 제외했습니다"

**최초 연동 확인 절차**: 인증키를 넣고 앱을 실행한 뒤, 위 배너가 뜨는지 본다.
0건이면 필드명이 맞는 것이다.

### 4.2 오류 코드 매핑

공공데이터포털 공통 에러코드(30 = 인증키 미등록, 22 = 트래픽 초과, 31 = 기간 만료,
03 = 결과 없음)는 공개 문서를 근거로 했으나 실응답으로 확인하지 못했다.
매핑에 없는 코드는 `SERVICE_ERROR` 로 떨어지므로 동작 자체는 안전하다.

### 4.3 전월세의 `monthlyRent` 부재 처리

전세 행에서 `monthlyRent` 태그가 아예 없는 경우를 `0`(전세)으로 본다.
값이 있는데 숫자가 아니면 실패로 처리한다(0 으로 때우지 않음).
태그 부재가 실제로 전세를 뜻하는지는 실응답으로 확인할 것.

### 4.4 화면 렌더링

Compose UI 는 문법 검사만 통과했다. Android SDK 와 Google Maven 에 접근할 수 없는
환경에서 개발되어 **APK 빌드와 화면 렌더링은 검증하지 못했다.**
특히 다음은 실기기 확인이 필요하다.

- Canvas 차트의 점 터치 판정 반경, 축 라벨 잘림
- Pretendard 폰트가 실제로 적용되는지 (테마 + Compose 양쪽)
- 스켈레톤 셔머 애니메이션, 당겨서 새로고침 동작

### 4.5 동탄 법정동 목록

작업지시서에 명시된 11개 동을 기본값으로 쓴다. 동탄2신도시 확장 구역(방교·중·금곡동)은
`DongtanUmd.EXTENDED` 로 분리해 두었고 기본값에는 없다. 목록의 최종 확정은 사용자 판단이다.
